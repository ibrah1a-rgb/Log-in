# خدمة الحسابات والحضور والمبيعات

خدمة تجريبية لمحل واحد، Python 3.11 أو أحدث، بدون مكتبات إضافية لاختبارات الخدمة والتشغيل المحلي. لا توجد خدمة منشورة أو حساب مدير جاهز. لا توجد كلمة مرور افتراضية.

## تجربة محلية على ويندوز

من مجلد `server`:

```powershell
py -3 app.py init-admin
py -3 app.py serve
```

الأمر الأول يسألك عن اسم مستخدم المدير، اسمه، وكلمة مرور لا تقل عن 12 حرفًا، مع التأكيد. لا يطبع كلمة المرور، ولا يعيد إنشاء المدير إذا كان موجودًا. الأمر الثاني يشغّل خادم تطوير على `127.0.0.1:8000`؛ ليس عنوانًا يصلح لجوالات الموظفين. لا تفتح هذا الخادم على الإنترنت مباشرة.

## ما يحتاجه التشغيل المشترك

- استضافة تشغّل تطبيق WSGI `app:application`، مع Python وقرص دائم لملف SQLite. اضبط `SHOP_DB` لمسار قاعدة البيانات على القرص الدائم.
- نفّذ `python app.py init-admin` مرة واحدة داخل بيئة الخدمة، ثم شغّل الخدمة عبر خادم WSGI إنتاجي خلف HTTPS. واجهة iPhone ترفض HTTP وتحويلات HTTP redirects.
- استخدم نسخة واحدة من الخدمة مع القرص المحلي نفسه؛ هذه ليست بنية متعددة النسخ. يلزم ضبط النسخ الاحتياطية والأذونات والحدود الزمنية وحجم الطلبات على بوابة الاستضافة قبل بيانات حقيقية.
- عنوان الخدمة في التطبيق هو أصل HTTPS، مثل `https://api.your-domain.example`، وليس رابط مستودع GitHub. العنوان المذكور هنا مثال فقط.
- عند استخدام reverse proxy اضبط مصدر عنوان العميل الموثوق في WSGI؛ التطبيق لا يثق تلقائيًا بترويسة X-Forwarded-For. دون هذا الإعداد سيشترك الموظفون في حد المحاولات الخاص بعنوان بوابة الاستضافة.

## سلوك الحسابات

المدير ينشئ حسابات موظفين فقط من التطبيق. إنشاء مدير متاح عبر أمر الإعداد المحلي حصريًا. الخادم يفرض الصلاحيات حتى لو عُدّلت واجهة التطبيق. لا توجد واجهة تسجيل ذاتي ولا ترقية ذاتية لدور المدير.

كلمات المرور تُجزّأ باستخدام PBKDF2-HMAC-SHA256 مع salt عشوائي و600,000 تكرار. الجلسات رموز عشوائية تُحفظ تجزئاتها فقط في قاعدة البيانات وتنتهي بعد 12 ساعة. تسجيل الخروج يبطل الجلسة على الخادم. تحديد معدل محاولات الدخول محفوظ بقاعدة البيانات. لا تُرفع قاعدة البيانات أو بيانات الحسابات إلى GitHub.

الحضور والمبيعات تُنسب لهوية الجلسة ووقت الخادم، وليس اسم الموظف أو الوقت المرسل من الجوال. لا يُسمح ببيع خارج دوام مفتوح. تكرار طلب البيع بنفس requestID لا يضيف عملية ثانية. المبلغ بالهللات هو إجمالي البيع؛ لا يُضرب في الكمية. الموظف يرى سجله فقط والمدير يرى آخر 500 تسجيل للجميع.

## Face ID

Face ID يفتح جلسة سبق إصدارها بعد اسم المستخدم وكلمة المرور، ولا ينشئ حسابًا ولا يغيّر صلاحياته. الخادم يستمر بالتحقق من صلاحية الجلسة. عند انتهاء 12 ساعة يُطلب إدخال كلمة المرور ثم إعادة تفعيل Face ID. يُحفظ رمز الجلسة في Keychain محمي بـbiometryCurrentSet وWhenUnlockedThisDeviceOnly. تغيير البصمات المسجلة قد يبطل الوصول إليه. لا نجمع صور الوجه.

## الاختبارات

```powershell
py -3 -m unittest -v
```

تغطي الصلاحيات، عزل بيانات الموظفين، تخزين كلمات المرور والرموز، انتهاء الجلسة وإبطالها، حدود تسجيل الدخول، تحقق المبيعات، وتكرار الطلبات.

## حدود النسخة

ليست جاهزة لاستخدام إنتاجي دون الاستضافة والاختبار على أجهزة فعلية. إعادة تعيين كلمات المرور وتعطيل الموظفين وإدارة جلسات جميع الأجهزة والتصدير والتقسيم إلى صفحات لم تُنفذ بعد. حد العرض 500 سجل فقط، لكن السجلات الأقدم تبقى في قاعدة البيانات. لا توجد مزامنة تلقائية في الخلفية أو قائمة انتظار دون اتصال. قد تتأخر نتيجة الشبكة؛ زر التحديث يجلب الحالة المؤكدة. سجل الحضور يؤكد ضغط الموظف للزر وليس وجوده الجسدي بالمحل.
